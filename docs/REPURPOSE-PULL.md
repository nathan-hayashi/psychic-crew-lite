# REPURPOSE-PULL.md — how this repo takes a blueprint (RPG-2)

The psychic-repurpose gallery publishes eleven re-instantiation blueprints as a graph:
frontmatter is the source, `docs/PULL-INDEX.md` in that repo is the projected index (capability
rows with the `requires` closure precomputed), and its `docs/PULL-PROTOCOL.md` is the law. This
file is Lite's consumer contract with it.

## The law, applied here

- **Resolve the sibling** via `PSYCHIC_REPURPOSE_PATH`, default `../psychic-repurpose` — the
  estate's relative-checkout convention. Absent checkout = no pull; nothing here degrades into
  a guess.
- **Pull by path, never by body.** A pull cites the blueprint's repo-relative path in the
  gallery. Pasting a blueprint body into this repo is the defect, not the feature: the parent's
  intake §6 carries the mechanical cap (length + fence bound), and this repo inherits the rule
  by convention.
- **Take the closure.** Pulling a blueprint takes its `requires` closure as the index
  precomputes it — a distrustful consumer re-derives from the PULL-EDGES block.
- **Trigger matching is judgment** — declared unasserted by the gallery itself; below 0.6
  confidence it is a FALLBACK question (rule 3), never a guess.

## The three pinned triggers (mirrors the parent pin)

| Defect class | Trigger phrase |
|---|---|
| `unbound-figure-drift` | a readme states a number the repo can recompute |
| `never-seen-failing` | a checker has never been seen failing |
| `opaque-gate-change` | non-author comprehension is a requirement |

## Honest limit

Lite carries NO mechanical arm for this contract — the parent suite binds the estate's vendored
pin unconditionally and diffs it against the live gallery when present; Lite consumes through
this doc and the orchestrator's law line. Stated here so the absence is a declaration, not a
gap someone discovers.
